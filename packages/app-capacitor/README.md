# App Capacitor

The native iOS and Android shell for Balebase. It renders the shared
application from `packages/app` with a native host: requests carry the
WebView's origin marker, emailed links open the hosted app, and downloads go
to the system share sheet. Native releases require iOS 18 or later and
Android 12 (API 31) or later.

On Android, the page draws under the system bars when the WebView reports
safe-area insets (WebView 140 and later). Layouts pad themselves with the
insets, and the status bar sits on an ink band with light icons. The
navigation bar's icons follow the app's theme (`src/systemBars.ts`). Older
WebViews keep the page clear of the bars.

## Production and staging store apps

Native store releases have two targets backed by shared shell and Fastlane
configuration:

| Tier | Native app identifier | Android variant | iOS scheme / configuration |
| --- | --- | --- | --- |
| Production | `com.balebase.app` | `release` | `App` / `Release` |
| Staging | `com.balebase.staging.app` | `staging` | `App-Staging` / `Release-Staging` |

`NATIVE_RELEASE_TIER` (`production` by default) selects the tier.
`capacitor.config.ts` sets the app ID and name from it, and the Vite build
defaults `VITE_API_URL` and `VITE_APP_URL` to the tier's hosted API and app.
`fastlane/lib/native_release_target.rb` maps the tier to its Gradle variant,
Xcode scheme and configuration, and secrets folder. Production releases read
`.secrets/prod/` and staging releases `.secrets/staging/`.

Android staging inherits the release build type. Each tier has its own upload
key, `.secrets/<tier>/balebase-upload.keystore`, registered with its Play app.
Both iOS schemes are committed and shared so Fastlane can archive either tier
without relying on Xcode's local autogenerated schemes.

Build or upload releases from the repository root:

```sh
./scripts/buildAndroidRelease.sh
./scripts/buildAndroidStagingRelease.sh
./scripts/uploadAndroidRelease.sh
./scripts/uploadAndroidStagingRelease.sh
./scripts/buildIosRelease.sh
./scripts/buildIosStagingRelease.sh
./scripts/uploadIosRelease.sh
./scripts/uploadIosStagingRelease.sh
```

All wrappers delegate to `scripts/lib/nativeRelease.sh`, which refuses a
`VITE_API_URL` or `VITE_APP_URL` that is not HTTPS on the tier's own host. Pass
`--help` to any wrapper for its options.

## Set up

Install the pinned Ruby with mise, then the Fastlane bundle:

```sh
mise install
cd packages/app-capacitor
bundle install
```

Fastlane loads the tier's `shared.env` when present, but only
`BALEBASE_ANDROID_KEYSTORE_PASS` from its `app.env`, which also holds the
tier's server secrets. Explicitly exported variables take precedence, and
neither secrets file may set the bundle's `VITE_*` hosts.

## Android sideload

Build and install the debug APK on a connected Android device:

```sh
bun run android:sideload:debug
```

Set `ANDROID_SERIAL` when more than one device or emulator is attached. The
release APK lane runs a release Capacitor sync first, which clears any
live-reload URL from the generated native config:

```sh
bun run android:sideload:release
```

Release builds sign with the selected tier's upload key when
`BALEBASE_ANDROID_KEYSTORE_PASS` is set. Without it, Gradle signs the release
APK with the debug signing config so it can still be sideloaded.

## Android instrumentation tests

```sh
bun run android:test:connected
```

Runs `android/app/src/androidTest` on a connected device or emulator, against
the web build from the last Capacitor sync. `WindowInsetsTest` checks that the
page asks to draw under the system bars and that the WebView ends at the
keyboard. On WebView 140 and later, Capacitor leaves the bars and cutouts to
the page's safe-area padding; older WebViews keep the page clear of them, and
the test checks that the bars' icons contrast with the window background
behind them. CI has no emulator, so run these after changing how the native
shell handles insets. Set `ANDROID_SERIAL` when more than one device is
attached.

## Android Google Play release

```sh
bun run android:build:google-play
bun run android:upload:google-play
```

Append `:staging` for the staging app. The build lane requires the tier's upload
key and password, runs a release Capacitor sync, and builds
`android/app/build/outputs/bundle/<variant>/app-<variant>.aab`.

By default, the build lane's `versionCode` is the larger of the latest PR
merged today and the next Play version code. It queries GitHub with `gh` first
and falls back to local squash-merge subjects like `(#153)`. Override the date
or PR with `ANDROID_RELEASE_MERGED_DATE=YYYY-MM-DD`,
`ANDROID_RELEASE_PR_NUMBER=<number>`, or Fastlane options
`merged_date:YYYY-MM-DD` and `merged_pr_number:<number>`. Set the final number
with `ANDROID_VERSION_CODE=<number>` or `build_number:<number>`, or take the
next Play version code with `next_google_play:true`; the upload wrappers do
the latter by default.

The upload lane builds the signed bundle, then uploads it with
`.secrets/<tier>/google-play-service-account-admin.json`. It skips Play
metadata, changelogs, images, and screenshots. The default track is `internal`;
override it with `GOOGLE_PLAY_TRACK=<track>` or `google_track:<track>`, and the
release status with `GOOGLE_PLAY_RELEASE_STATUS=<status>`. Validate without
committing the Play edit with `validate_only:true`.

## iOS TestFlight release

```sh
bun run ios:build:testflight
bun run ios:upload:testflight
```

Append `:staging` for the staging app. The lane runs a release Capacitor sync,
verifies the generated native config is fully bundled, installs the App Store
certificate and profile with read-only `match`, and builds
`ios/App/output/Balebase.ipa`. Signing requires a Developer Team ID via
`IOS_TEAM_ID`, `APPLE_TEAM_ID`, `DEVELOPMENT_TEAM`, `FASTLANE_TEAM_ID`,
`TEAM_ID`, or `team_id:<id>`, and the `MATCH_*` repository settings. The archive
resolves Swift packages only from the committed `Package.resolved`.

The marketing version is this package's version, as Android's version name
is. The build number follows the Android convention, checked against TestFlight
when App Store Connect credentials are available: `APP_STORE_CONNECT_KEY_ID`,
`APP_STORE_CONNECT_ISSUER_ID`, and `.secrets/<tier>/AuthKey_<key-id>.p8`. The
upload lane only uploads by default; see `fastlane/lanes/testflight_upload.rb`
for submission and external distribution options. `Info.plist` declares that
the app uses no non-exempt encryption, so builds skip the export compliance
question.

Each tier's `shared.env` holds `TEAM_ID`, the App Store Connect key ID and
issuer ID, and the `MATCH_*` settings of the shared `match` repository. That
repository keeps the team's Apple Distribution certificate and a
`match AppStore <app ID>` profile for each app. Create a missing profile, or
renew an invalid one, with the API key:

```sh
bun run ios:create:appstore-profile
bun run ios:create:appstore-profile:staging
```

Pass `force:true` to regenerate it, as after the bundle ID's capabilities
change. Release builds only read it.

## Store build numbers

```sh
bun run store:build-numbers
bun run store:build-numbers:staging
```

Reads the latest build numbers from Google Play (the `production`, `beta`,
`alpha`, and `internal` tracks) and App Store Connect. Missing credentials or
one store's failure do not block the other lookup.
